# Architecture — pipeline, data model, scripts, site, design system

The map for anyone touching the code. **Edit canonical inputs and generators; regenerate their outputs.** Provider facts live in `data/providers.json`, but the pipeline also consumes companion datasets, editorial metadata, hand-written documentation and site templates.

## 1. The data-first pipeline

```
data/providers.json   ─┐
data/programs.json    ─┤──►  scripts/build.mjs  ──►  README.md, site/badge-freshness.json,
data/*schema.json      │                              collections/*.md, docs/credit-programs.md,
                       │                              docs/comparison-dimensions.md,
                       │                              site/index.html (SSR rows injected),
                       │                              site/{collections,models,guides,p,programs,legal}/,
                       │                              site/guides-and-collections/ (unified hub),
                       │                              site/api/v1/*, site/llms.txt, site/llms-full.txt,
                       │                              site/sitemap.xml, site/updates.html and site/updates/page/*,
                       │                              site/feed.xml, site/changes/ + site/changes.xml
                       │                              (weekly field-level change feed),
                       │                              site/state/ (monthly state reports),
                       │                              site/badges/*.json, site/compare/ (compare view),
                       │                              site/shared-rules.js, site/shared-rows.js,
                       │                              site/shared-sort.js, site/shared-compare.js (gitignored)
                       └──►  generated regions and outputs; preserve authored inputs.
```

- **Canonical inputs:** `data/providers.json` and `data/programs.json`, plus the companion files listed below. Schema files describe contracts; they are not generated from provider records.
- **Other build inputs:** `data/not-free.json` (the one source of the README's "Notably NOT free" section and of `/not-free/`), `data/best.json`, `data/editorial.json`, `data/provider-summaries.json`, `data/sponsorships.json`, `data/repo-stats.json`, `data/probe-report.json`, `data/gpu-compute.json`, `data/coding-tools.json` and `data/coding-tools-own-key.json`. Quotes and quote reports are validated evidence records; follow [quotes.md](quotes.md) when changing them.
- **Hand-written inputs with generated regions or pages:** `README.md`, `site/index.html`, `CITATION.cff`, `docs/credit-programs.md` and `docs/comparison-dimensions.md` retain authored text around generated sections or fields. `CONTRIBUTING.md` and `docs/methodology.md` generate their matching site pages. Edit authored text at its source and run the build. Other docs, scripts, styles and browser code remain hand-maintained.
- **`scripts/build.mjs`** reads the data and writes everything. It is idempotent for the same inputs, Git history and reference day. Date-relative and history-derived exceptions are described below.
- **CI:** `verify.yml` installs the locked development tools with lifecycle scripts disabled, then runs `validate` + `check-links` + `check-og` (OG images exist and match the dataset) + `check-history` (git-mined history) + the pipeline tests on every PR, plus a **blocking drift check**: it rebuilds the derived files and fails the PR if they are out of sync with the data. The author regenerates locally (`npm run build`, and `npm run og` when needed) and commits the results in the same PR, so a change ships complete. `regenerate.yml` (off by default, then shadow mode) rebuilds the derived files after each merge from `main` and, through a dedicated GitHub App, opens a draft pull request when they differ; it only writes paths allowed by `scripts/generated-targets.mjs` and does not replace local regeneration until the switch described in [regeneration-bot.md](regeneration-bot.md). `regenerate-preview.yml` is its pull-request side: on each pull request that touches data, scripts, docs or derived files it rebuilds with a read-only token, lists the derived files a fresh build would change, uploads them as the `regen-preview-patch` artifact and reports what the planned gate would decide; it never fails on drift and is not a required check. The daily deploy (`pages.yml`) refreshes GitHub stars before building and commits nothing. Provider re-verification, badge regeneration, probes and the `models_free` backfill (`npm run models`) stay local and on-demand. **Corollary: nothing may be relative to the *current date*** in committed generated files — everything committed must be byte-stable for a given dataset (the "NEW" badge and the freshness colours are computed from the data's own newest date, `datasetAsOf`, so they are deterministic and safe in committed files; provider `/p/` pages are gitignored precisely so they can use the current date).
- **Weekly issue metadata:** `weekly-worklist.yml` runs the dependency-free `refresh-worklist.mjs --write` against trusted main Mondays at 09:17 UTC and on manual main dispatch, serializing runs. It replaces only issue #4's generated body from the shared `stalenessWorklist` renderer, with a UTC date and immutable dataset commit link. Preview locally with `npm run worklist:refresh`; see [manual recovery](update-playbook.md#recover-a-stale-issue-worklist) for delayed or disabled schedules. It makes no provider requests, verifies no claims and edits no dataset or site/badge artifacts. Human review and the clean-worktree handoff remain required for provider changes.
- **Monthly source checks:** `monthly-checks.yml` runs `scripts/monthly-checks.mjs --publish` on the 1st of each month at 06:23 UTC and on manual dispatch, from trusted main with `contents: read` and `issues: write` only. It runs `check-links`, `check-sources` and `verify-quotes` (no `--write`) and opens one `Monthly source check: YYYY-MM` issue when any fails, comments on the open one if it exists, and closes it after a clean run. The issue carries only our own URLs, ids and statuses, never page text; provider CDNs often answer runners with 403, so a failure there is a lead to re-check by hand, not a data change.
- **Monthly contributor issues:** `monthly-issues.yml` runs `scripts/monthly-issues.mjs --publish` on the 1st of each month at 06:37 UTC and on manual dispatch, from trusted main with full git history, `contents: read` and `issues: write` only. It opens `Free tier changes — <Month YYYY>` (labels `data`, `help wanted`) for the month that ended, with providers added and removed (month-end snapshots) and field changes (`lib/history.mjs`, `lib/changes.mjs`, the same history as `/changes/` and `/state/`), and `New provider candidates — <Month YYYY>` (label `help wanted`) for the current month, with the non-text share against the 35% guardrail. An issue with the same title, open or closed, is never opened twice; a shallow clone fails the history plausibility check instead of reporting an empty month. It never edits data.
- **Weekly source watch:** `source-watch.yml` runs `scripts/source-watch.mjs --publish` Mondays at 06:41 UTC and on manual dispatch, from trusted main with `contents: read` and `issues: write` only and no secret. It re-reads every page cited in `data/quotes.json` as `quotes:add` does and keeps one "Source watch: quotes to re-check" issue (missing quotes per provider; fetch errors only after two runs in a row), closed when a run is clean. Its run-to-run state is a hidden comment in that issue and the full report a run artifact; nothing is written to the repository. See [the playbook](update-playbook.md#source-watch).

  *E2E-verified 2026-08-13 (PR #127): a bare data change without regenerated files fails the drift step (verify run `31746567051`, exit 1, with the remediation instructions in the step summary); pushing the same change with the regenerated files committed passes (run `31746721656`).*

  **The freshness badge is not committed.** It has to be date-relative — a freshness badge that only moves when the data moves is not measuring freshness — so the build writes it to `site/badge-freshness.json` (gitignored) and every deploy, including the daily one, publishes it; the README badge reads it from the site. Nothing may assert that a badge built on one day equals one built on another — the test in `build.test.mjs` checks internal consistency instead.

  **Release-only lines.** `version` and `generated` in `data/providers.json` are the dataset release: there `generated` is the release date and moves only with `version` (`npm run release:prepare`; `scripts/check-release-stamp.mjs` fails a pull request that moves it otherwise). Only `date-released` in `CITATION.cff` prints that stamp. Every public date keeps its documented meaning, "the date of the last dataset change" ([api.md](api.md)): the build derives it as `datasetAsOf`, the newest of the stamp and every date recorded on a provider (`last_verified`, `added`, `last_probed`, `data_policy`/`free_limits`/`no_expiry` `checked`; `scripts/lib/release-stamp.mjs`), from the committed data only, and uses it for the API envelopes, the CSV `dataset_generated` column, the site's `providers.json`, `llms.txt`, sitemap `lastmod`, "Data of …" lines, row ages and the score. Changelog entries are fragments, `changes/unreleased/*.md`, moved into `CHANGELOG.md` by the release. The home page inlines its data one provider per line. So a data pull request no longer edits a canonical line that every other data pull request edits; the derived date still moves when a pull request records a newer date, which rewrites date lines in aggregate outputs (CSV column, row ages, sitemap, fingerprints). Those are regenerated, never hand-merged: two pull requests from the same day write identical lines, and otherwise `npm run sync-main` rebuilds them.

**The gitignored derived files are pinned too.** `derived-fingerprints.json` (a sha256 of every build output under `site/` that is not tracked by git) is itself a drift-gate target: a change to any gitignored derivative - `models/`, `api/`, `legal/`, `programs/`, `llms.txt`, `shared-rules.js`/`shared-rows.js`, ... - is visible in review and fails CI until the author commits the regenerated fingerprint. The set is derived from `git ls-files site/` at the end of `build.mjs`, so it stays in sync with `.gitignore` automatically. The deliberate exclusions are the date-relative outputs — `site/p/` (provider pages render "verified Xd ago" relative to the current day, the same reason they are gitignored at all) and `site/badges/` (each per-provider badge turns yellow past 60 days and red past the SLA, so its bytes change with the calendar, not the data) — and the git-log-derived files — `updates.html`, `updates/page/*`, `feed.xml`, `api/v1/history.json`, and the weekly change feed and monthly reports mined from the same history (`changes/`, `changes.xml`, `api/v1/changes.json`, `state/`) — whose content embeds the commit hash/subject or dates of the build history, so it shifts across a squash merge and cannot be deterministically pinned (they are regenerated on every deploy).

**Lighthouse is split by stability.** `lighthouse.yml` measures twenty-one built pages (including `/find/`). On every PR the required check runs accessibility and SEO once per page (`scripts/lighthouse-gate.mjs --mode=accessibility-seo`; deterministic, so one run is a stable verdict). Performance, which moves between runs on a shared runner, is judged on the median of three runs per page after each push to `main` and nightly (`--mode=performance`); a failure opens or updates one issue and a later clean run closes it. Thresholds live in `scripts/lib/lighthouse-gate.mjs`.

**Deploys are verified live.** `pages.yml` runs a `verify-live` job after every deploy: it re-checks the sitemap parity against the live site (`npm run check-live`, retrying `FLLM_LIVE_ATTEMPTS` times for edge propagation) and smoke-tests every URL of the published sitemap (`npm run smoke-live`, retrying only the URLs that did not answer 200, with a doubling wait), so a deploy that serves stale or broken pages fails the workflow.

## 2. Data model

### `data/providers.json`
Top level: `{ $schema, version (semver, the dataset release), generated (YYYY-MM-DD), source, note, providers: [...] }`.
Schema in `data/schema.json`; validated by `scripts/validate.mjs`. Canonical byte-format enforced by `scripts/_serialize.mjs` (the `ORDER` array). **Field order in the file MUST match `ORDER`** or the serializer self-test fails.

Per-provider fields (grouped for reference; the authoritative serialization order is `ORDER` in `scripts/_serialize.mjs`):

| field | type | notes |
|---|---|---|
| `slug` | kebab-case, unique, never reused | stable ID; drives `/p/<slug>.html`, `env_key`, OG path |
| `name` | string, unique | display name |
| `category` | `ongoing` \| `trial` | splits README tables + site |
| `free_type` | `perpetual` \| `renewing-quota` \| `recurring-credit` \| `trial-credit` | finer shape |
| `free_tier` | string | what you actually get, concrete |
| `rate_limits` | string | |
| `notes` | string | "the catch" — the fine print that bites |
| `best_for` | string \| null | editorial one-liner (subtitle in table + card) |
| `modalities` | array of `text,vision,image,audio,embeddings,rerank,ocr` | |
| `models_free` | array of strings \| null | SAMPLED model IDs (attribute, not core claim). Refreshed by `fetch-models.mjs`. |
| `models_url` | url (optional) | the provider's own model catalogue page; may include paid models |
| `expires` | string \| null | e.g. "30 days" |
| `docs_url` | url | **primary source** — provider's own page. Required when `verified:true`. Also drives the "Visit website" button. |
| `phone_required` | true/false/null | null = not confirmed |
| `card_required` | true/false/null | |
| `commercial_ok` | true/false/null, or `"conditional"` in the canonical dataset | `"conditional"` requires `commercial_ok_condition`; API v1 projects it to null and scoring/coverage treat it as unconfirmed |
| `commercial_ok_condition` | string \| null | concise provider condition; required only for `commercial_ok: "conditional"`, retained when API v1 projects the flag to null |
| `openai_compatible` | true/false/null | |
| `openai_base_url` | url \| null | only when `openai_compatible !== false` |
| `is_text_llm` | boolean (required) | free offering gives text/chat LLM API access; eligibility for the top 10 |
| `model_tier` / `model_tier_source` | 0-4 / object, or both null | derived from a cited LMArena rating (thresholds in `lib/model-tier.mjs`); validated against the rating |
| `free_limits` | object \| null | published numeric limits with `source` and `checked`; never estimated |
| `no_expiry` | object \| null | trial credits only: the provider's own statement that the credit does not expire, with `source`, `checked` and a short `quote`; validated, never combined with a non-null `expires` |
| `anonymous_access` | object \| null | the provider's own statement that the API works with no account, with `source`, `checked`, a short `quote` and an optional `note`; validated; drives the `anonymous-access` collection |
| `published_speed` | array (optional) | speed figures the provider publishes for models of its `models_free`, each with `source`, `checked` and a `quote`; provider claims, never measurements; validated (`lib/published-speed.mjs`) |
| `field_checks` | object (optional) | per tri-state flag, why it holds its value: `status` (`stated`, `source_silent`, `needs_account`, `sources_disagree`), `checked`, `sources`, optional `quote` and `note`; validated (`lib/field-checks.mjs`) |
| `data_policy` | object \| null | what the provider says about prompts: `trains_on_prompts`, `retention`, with `source` and `checked`, optional `quote`, `note` and `plan_named`; never estimated, shown on the provider page only when set |
| `playground_url` | https url (optional) | provider-owned no-code playground; requires a non-empty `docs_url`; adds a "Try it" button |
| `keys_url` / `keys_url_source` | https url (optional, together) | the provider's own page where a signed-up user creates an API key, exactly as its docs link it, and the docs page that links it; never guessed; requires a non-empty `docs_url`; adds a "Get a free key" button between the free limits and the quickstart |
| `env_key` | UPPER_SNAKE | secret NAME for probe/fetch-models. **STRIPPED from all public output** (homepage payload, site/providers.json, /api) except the two client configs (`api/v1/openai-clients.json`, `api/v1/litellm.yaml`), whose purpose is to tell users which variable to put their own key in. Never the value. |
| `verified` | boolean | true = independently confirmed against own docs on `last_verified` |
| `last_verified` | YYYY-MM-DD \| null | must be null when `verified:false` |
| `added` | YYYY-MM-DD (optional) | provenance: when it entered the dataset. Drives the NEW badge (≤45d) in the shared row code — SSR and client alike. Set once; never changes. |
| `last_probed` | YYYY-MM-DD \| null | live-probe date (probe.mjs) |
| `probe_status` | `live`/`auth-ok`/`auth-failed`/`tier-ended`/`rate-limited`/`error`/null | `live` → "live-tested" badge; `auth-ok` → credentials checked, no inference |

The serializer **skips absent keys**, so new optional fields only appear on providers that have them, and existing rows are untouched.

### `data/programs.json`
`{ generated, note, startups: [...], research: [...] }`. Each entry:
- startups: `{ name, url, what, funds, who }`
- research: `{ name, url, audience, what, funds, who }` (audience required)
- `funds`: `yes` = first-party LLM-API credits · `partial` = cloud/compute usable for managed LLM APIs · `no` = training/perks/adjacent infra.

## 3. Scripts (`scripts/`, npm scripts in `package.json`)

- **`build.mjs`** (`npm run build`) — generates everything (see §1). Idempotent. Uses git (`execSync`) for the updates page/RSS and the per-provider change history; graceful if git is absent. Note: needs a **full clone** (`fetch-depth: 0` in CI) for that history.
- **`validate.mjs`** (`npm run validate`, part of `npm test`) — first validates `data/providers.json` against `data/schema.json` with the locked JSON Schema tooling (Draft 2020-12 + standard formats), then applies repository-specific integrity rules: unique slug/name, verified→(last_verified+docs_url), `added` freshness, programs.json shape and probe-report consistency. Exit 1 on any issue.
- **`_serialize.mjs`** — the ONE canonical serializer (`ORDER`, `serialize`, `roundTripError`). Shared by fetch-models + probe so they never drift. `roundTripError` asserts byte-exact.
- **`fetch-models.mjs`** (`npm run models`, `--write`, `--self-test`) — refreshes `models_free` from each provider's own `/models` endpoint. PUBLIC (no key): openrouter (`:free`), pollinations (regular, non-paid-only models of `gen.pollinations.ai/v1/models`), nvidia-nim, modelscope, typhoon (ollama-cloud was dropped: its public catalogue does not identify the free subset). KEY-gated (only if env var set): groq, cerebras, sambanova, scaleway. Real IDs only; a fetch failure leaves the field untouched. Deterministic publisher-diverse sample (largest publisher catalogues first), cap 8; keyed requests refuse redirects and every body is read with a byte cap.
- **`discover.mjs`** (`npm run discover`, `--write`, `--json`) — diffs OpenRouter's `:free` catalog vs a stored snapshot (`data/discover-snapshot.json`) and reports NEW free models + publishers not listed as first-party (leads). Never edits the dataset.
- **`probe.mjs`** (`npm run probe`) — live-tests each free tier with a real key from `process.env[env_key]`; writes `last_probed`/`probe_status`. Generic OpenAI-compatible path only so far. Run on demand, locally: `node scripts/probe.mjs --write --auth-only`; see [live-testing.md](live-testing.md).
- **`og.mjs`** (`npm run og`) — renders social PNGs with the `@resvg/resvg-js` development dependency: site-wide `og.png`, per-provider `site/og/p/*.png`, per-guide and per-collection; also writes `site/og/manifest.json` so `check-og.mjs` can fingerprint them. **NOT run by the Pages build** → the PNGs must be COMMITTED (`site/og/` is not gitignored). Run `npm run og` after adding providers/guides/collections.
- **`staleness.mjs`** (`npm run worklist`) — re-verification worklist, printed locally, report-only: 🔴 overdue (>90d), 🟡 due soon (61–90d), ⚠️ never verified, plus this week's batch and the cliff watch (many entries sharing one verification date). Same buckets as the badge, imported from `rules.mjs`; see [freshness-sla.md](freshness-sla.md). The weekly pass follows it ([update-playbook.md](update-playbook.md)).
- **`refresh-worklist.mjs`** (`npm run worklist:refresh`, explicit `--write`) — previews the same worklist with UTC date and checked-out HEAD provenance; only `--write` publishes issue #4's body through JSON stdin to `gh`. Skips identical bodies; closed/missing issues and failed writes fail visibly. The weekly workflow uses it without installing dependencies. Entire-body replacement resets checkboxes; discussion belongs in comments, and publication is not provider verification.
- **`reverify.mjs`** (`npm run reverify`, `--batch N`, `--fetch-for-human-review`) — prints the local re-verification worklist without network access by default. A human-only opt-in fetches provider prose through the bounded public-URL transport and writes warning-labelled dossiers under the operating system's temporary directory, outside the checkout. Agents may handle only the later human-authored edit in a fresh worktree that never contained current or legacy dossiers.
- **`check-og.mjs`** (CI) — every committed OG PNG must exist AND match the dataset: recomputes the fingerprints in `site/og/manifest.json` from `data/providers.json`. Pure Node, with no image-rendering dependency, so it checks the fingerprint without rendering images.
- **`check-history.mjs`** (CI) — cheaply validates the git-mined per-provider history (two git processes, no build) before the full test suite.
- **`check-links.mjs`** (`npm run links`, part of `npm test`) — validates local Markdown file paths across tracked and non-ignored new Markdown files, including nested docs, release instructions, templates and package READMEs. Absolute paths and paths escaping the repository are rejected, including Windows forms on Linux. Query strings and fragments are stripped before checking paths; heading anchors and external destinations are not validated. Never touches the network. The external `docs_url` sweep is a local on-demand pass in the [update playbook](update-playbook.md); genuine failures (not 401/403/405/429 bot-blocks) are reported for human follow-up; the checker does not open issues.
- **`probe-cron.sh`** — the VPS weekly cron helper (Infisical → probe → models → build → reviewed diff). It never stages or pushes generated output; a human opens the pull request.

npm scripts: `build, validate, links, worklist, worklist:refresh, reverify, models, discover, probe, og, test (validate + links + test suites), check (validate + build + diff-gate), check-live (committed sitemap vs deployed), smoke-live (every published sitemap URL answers 200)`.

## 4. Site structure (`site/`)

**IMPORTANT two-places rule:** the homepage `site/index.html` is **HAND-WRITTEN**; the build only injects the SSR table rows (`<!-- AUTOGEN:rows -->`), the stat tiles (`AUTOGEN:stats`), the first-use strip (`AUTOGEN:firstuse`), the inline JSON payload (`<!-- AUTOGEN:data -->`) and the CSP, theme guard and Dataset blocks. Every OTHER page is generated by `build.mjs` using `siteHeader(prefix)` / `siteFooter(prefix)` / `htmlPage(...)`. So **when you change the header/footer/nav you must edit BOTH** `site/index.html` AND the `siteHeader`/`siteFooter` functions in build.mjs. Same for the SVG icon sprite (one copy in build.mjs `SPRITE`, one inline in `site/index.html`).

Pages:
- **`/` (index.html)** — hero, first-use strip ("New here? How this list works": what the list is, what verified means, how to use it, with counts and the oldest and newest verification dates from the data, `scripts/lib/home-first-use.mjs`), controls, SSR explorer table + inline dataset, client explorer JS (filter presets, sort, category/modality filters, URL-sync) in `site/explorer.js`. Works with no JS (SSR rows). Row markup is **single-source**: one `explorerRowHtml()` in `scripts/lib/rows.mjs` — build.mjs server-renders with it (`now: data.generated`, deterministic, drift-safe) and serializes it to `site/shared-rows.js` (`window.FLLM_ROWS.rowHtml`), which the client calls with `now: Date.now()` for live freshness. The shared scoring/flag/freshness logic lives in `scripts/lib/rules.mjs`, serialized to `site/shared-rules.js` (`window.FLLM_RULES`); both files are build-emitted and gitignored. Never keep row markup in build.mjs or explorer.js.
- **`/models/`** — searchable model→provider index from every `models_free`.
- **`/guides/<slug>`** — data-generated SEO guides (`GUIDES` in build.mjs): filter, top pick, FAQ (`FAQPage` JSON-LD), related guides, per-page OG. The unified **hub lives at `/guides-and-collections/`** (two sections — guides and collections); the old `/guides/` and `/collections/` roots are meta-refresh redirects to it. Long-form guides share `/guides/` (`LONG_GUIDES` in `scripts/lib/long-guides.mjs`: OpenAI alternatives, production checklist, no card and no phone, the embeddings, speech, OCR and image-generation guides, which replaced the list guides at those slugs, and the use-case guides (coding assistants, RAG, AI agents, a chatbot side project, students; `group: 'use-case'`, their own hub section)): editorial copy whose every number, limit, flag and provider list is computed from `data/providers.json` and `data/not-free.json` (the students guide also reads `data/programs.json`, the coding guide `data/coding-tools-own-key.json`) at build time; their social images are fixed-text section images (`SECTION_OGS` in `lib/og.mjs`).
- **`/collections/<slug>`** — editorial collections (`COLLECTIONS` in build.mjs). Each has repo markdown (`collections/*.md`) + live HTML, FAQ on higher-traffic ones, per-collection OG. (`/collections/` root redirects to the hub.)
- **`/p/<slug>`** (file `site/p/<slug>.html`) — provider cards, clean canonical URL. Gitignored + regenerated on deploy → may use the current date (freshness read-out). Badges, "Official docs" + "Visit website" + "Report a change" (opens the `inaccuracy.yml` issue form with `provider` and the `[outdated] <name>` title prefilled), meta table, free-models block, modality-aware quickstart, change history (from git).
- **`/programs/`** — startup + research credit program pages, from programs.json.
- **`/compare/`** — provider compare view. `/compare/?compare=a,b` (2–4 slugs; `?compare=` on the home page redirects here) renders a side-by-side table in the browser (`site/compare.js`); `/compare/<a>-vs-<b>/` are static pages for a small, deterministic set of pairs: the editorial picks in `data/best.json` compared pairwise where they share a modality, ordered by rank, at most 4 pages per provider and 30 in all. Both render with `compareTableHtml()` in `scripts/lib/compare.mjs` (serialized to `site/shared-compare.js`, `window.FLLM_COMPARE`). The pages are gitignored, pinned in `derived-fingerprints.json` and listed in the sitemap, so they must not depend on the current date. Provider pages link to the comparisons they appear in.
- **`/find/`** — "Find my free API": a step-by-step form (what you build, card, phone, commercial use, no training on prompts, OpenAI compatibility) and a ranked shortlist. Questions, filters, the URL hash (`#use=chat&card=no`), the explorer link and the result markup live in `scripts/lib/find.mjs`, serialised to `site/shared-find.js` (`window.FLLM_FIND`); the page body is `scripts/lib/find-page.mjs`; `site/find.js` only wires the form. No ranking of its own: every answer is an explorer filter chip and the order is `recommendedCmp` (`shared-rules.js`); providers whose only gap is a field that is not confirmed are listed apart, never as matches. The page inlines `findPayload()` (only the fields it reads; `keys_url` when present). Gitignored and pinned in `derived-fingerprints.json`; in the sitemap. Without JavaScript it links to the explorer with matching filters.
- **`/api/v1/`** — static JSON API: `providers.json`, `programs.json`, `history.json`, `changes.json` (field-level from/to changes grouped by ISO week, last 12 weeks), `best.json`, `index.json` (manifest), `schema.json` (copy of `data/schema.json`), slices (`ongoing,trial,perpetual,no-card,no-phone,commercial,openai-compatible`), `modality/<m>.json`, plus client configs for the verified OpenAI-compatible providers: `openai-clients.json` and `litellm.yaml` (a LiteLLM proxy `model_list`, generated by `scripts/lib/client-config.mjs`). Every JSON object carries `version`+`generated`. Stability and versioning policy: [api.md](api.md).
- **`/not-free/`** — the APIs people expect to be free and are not, from `data/not-free.json` (`scripts/lib/not-free.mjs`), which also renders the README's `AUTOGEN:not-free` region. Quotes are copied from `docs/sources.md` or referenced by id from `data/quotes.json`; `scripts/use-data-pages.test.mjs` checks both. Alternatives: verified ongoing providers sharing a modality, best score first.
- **`/embed/`** ("Use the data") — widget snippet generator and preview (`site/embed.js` re-runs `widget.js`), the verified and per-provider badges, the data files, and BibTeX/APA from `CITATION.cff` (`scripts/lib/citation.mjs`, `scripts/lib/embed-page.mjs`). Provider pages end with a link to their badge there.
- **`llms.txt` + `llms-full.txt`** — llmstxt.org index + full provider expansion, for AI agents.
- **`/updates.html` + `/feed.xml`** — from git log.
- **`/changes/` + `/changes.xml`** — "What changed this week": field-level changes (field, from, to) grouped by ISO week, newest first, the last 12 weeks ending at the newest change; one RSS item per week. Logic in `scripts/lib/changes.mjs` (pure, fixture-tested); the before/after values come from the `changes` array the history miner (`scripts/lib/history.mjs`) attaches to each `changed` event, which `api/v1/history.json` strips to keep its published shape.
- **`/changes/#months` + `/state/YYYY-MM/`** — monthly "State of free LLM APIs" report, one per month (the index of the months is a section of `/changes/`, the one page for what changed; `/state/` is a redirect page to it, because GitHub Pages cannot send a server redirect) with a committed revision of `providers.json`. Every number is computed (`scripts/lib/state.mjs`) from that month's last committed revision, the mined history and the `added` field: counts by category and modality, verified share, oldest/median verification age as of the month end (the newest month is measured at its last revision), field changes and providers changed that month, providers added that month. Only `/changes/` is in `sitemap.xml` (`/state/` is a redirect page and is left out): the per-month URLs follow commit dates, which a squash merge can move into another month, so listing them would make the drift-gated sitemap non-deterministic.
- All of the above is produced by `build.mjs` alone (the deploy already runs it); the daily deploy refreshes the star count first (`scripts/refresh-stars.mjs --keep-on-failure`) and commits nothing. The separate weekly issue publisher changes no build outputs. **`/legal/`** — privacy/terms (noindex). **Analytics:** by default only Cloudflare Web Analytics, which Cloudflare injects at the edge (cookieless, outside the build); `build.mjs` only adds its hosts (`static.cloudflareinsights.com`, `cloudflareinsights.com`) to the CSP and describes it on the privacy page. When the deploy has the repository variable `GA_MEASUREMENT_ID`, `build.mjs` (via `scripts/lib/analytics.mjs`) adds `consent.js`, a first-party opt-in banner (Accept all / Reject all / Customize, with two independent categories: analytics, and advertising & personalised measurement, which enables Google signals) with a "Cookie settings" control in every footer, the Google Analytics and Google signals hosts to the CSP, and the matching privacy text; gtag.js loads only after at least one category is granted (Consent Mode v2: all denied by default, then updated with exactly what was granted). With the variable empty the build emits no Google analytics code at all. **`/badges/`** — per-provider shields.io endpoint JSON. Plus `sitemap.xml`, `sitemap-index.xml` (lists `sitemap.xml` and `sitemap-state.xml`; the one URL to submit in Search Console), `robots.txt`, `CNAME`, the IndexNow key file `<key>.txt` (see below), `og/`, `favicon.svg`, `fonts/`, `styles.css`, `site.js`, `explorer.js`, `widget.js`.

Client JS: `site/site.js` (loaded on EVERY page) = theme toggle, live GitHub stars (6h cache), "/" to focus search, code-block copy buttons, mobile nav toggle. `site/explorer.js` = homepage explorer logic, including keyboard row navigation (roving tabindex: arrow Up/Down, Home/End, Enter opens the provider page; the movement rule is `rowKeyTarget` in `scripts/lib/rows.mjs`). `site/compare.js` = the compare view picker. `site/widget.js` = the embeddable widget. All scripts run under a hash-based Content-Security-Policy.

### IndexNow (after each deploy)

The deploy announces the URLs it adds or changes to [IndexNow](https://www.indexnow.org) (`api.indexnow.org`, which shares them with Bing, Yandex and the other participating engines), so they need not wait for a crawl. Google does not take part; it reads the sitemaps.

- **Key.** `site/96087c6012c181da7cf7f9dcc88f9996.txt`, served at the site root, holds the key and nothing else. The key is public by design: serving it proves the site owns the host, and it authorises nothing but these pings. It was generated once and is committed. It is not build output (`scripts/generated-targets.mjs` leaves it out of the drift gate) and it is not a page (not in the sitemap). To rotate it, commit a new file, update `INDEXNOW_KEY` in `scripts/lib/indexnow.mjs`, and delete the old file.
- **Which URLs.** `pages.yml`, build job, after `build.mjs` and before the upload: `node scripts/indexnow.mjs --plan` compares the built `sitemap.xml` and `sitemap-state.xml` with the copies still live (the previous deploy). URLs that are new, or whose `lastmod` changed, become the job output `indexnow_urls` (a JSON array), newest first and capped at 100 (`URL_CAP`).
  - A live sitemap that cannot be read is skipped, so none of its URLs are sent.
  - A live sitemap that answers 404 counts as empty.
  - Removed URLs are not sent; the engines see the 404.
  - The daily scheduled deploy usually changes no `lastmod`, so it sends nothing.
- **Submit.** The `indexnow` job runs after `verify-live`, and only when the list is not empty: `node scripts/indexnow.mjs --submit` first checks that the key file answers on the live site, then POSTs `{host, key, keyLocation, urlList}`, and logs the status (200 submitted, 202 key validation pending, 403/422 key or host problem, 429 throttled).
- **Never fails the deploy.** Both steps are `continue-on-error`, have a `timeout-minutes`, use a 15 s timeout per request, and the script exits 0 on every path. The job has a read-only token (`contents: read`), uses no secret, pins its actions by SHA, and receives the URL list through the environment, never interpolated into the script.

### GA4 product events (only with analytics consent)

When analytics is configured (`GA_MEASUREMENT_ID`, see above) and the visitor has granted the **analytics** category, `consent.js` (source `scripts/lib/consent.client.js`) sends these custom events through one delegated listener per event type. Before consent, with only the advertising category, or with everything rejected, `track()` is a no-op. No parameter carries personal data: values come from fixed lists or validated slugs, and the only free text, the explorer's search box, is normalised, cut to 60 characters and dropped when it looks like an email address or a long number.

| Event | Parameters | Fires when |
| --- | --- | --- |
| `outbound_provider_click` | `provider` (slug), `link_type` (`docs`, `keys`, `website`, `playground`, `models`, `limits_source`, `data_policy`) | a link carrying `data-provider` / `data-link` is clicked or middle-clicked. The build adds both attributes (`scripts/lib/provider-links.mjs`) on provider pages and static comparisons. |
| `copy_snippet` | `snippet` (`curl`, `python`, `env_key`, `embed`, `badge`, `citation`, `api_url`, `other`) | a code block's Copy button (the kind is the block's `data-snippet` when it is `embed`, `badge` or `citation`, else read from its first word) or an API endpoint's Copy button |
| `explorer_filter` | `filter_name` (`category`, `modality`, `no_card`, `no_phone`, `commercial`, `text_only`, `no_training`, `openai_compatible`, `verified`), `filter_value` (`all`/`ongoing`/`trial`, a modality option, or `on`/`off`) | a category button, the modality menu or a filter chip changes |
| `explorer_sort` | `sort_key` (`recommended`, `name`, `category`, `free_tier`, `notes`, `verified`), `sort_dir` (`asc`/`desc`) | a column header or the sort menu |
| `compare_view` | `pair` (`a-vs-b` for a static page, `a,b[,c,d]` for a shared `?compare=` link) | once per page view of a comparison |
| `collection_view` | `collection` (slug) | once per page view of `/collections/<slug>` |
| `api_download` | `file` (path, such as `providers.json` or `api/v1/litellm.yaml`) | a link to one of the site's own data files: `providers.json`/`.csv`, `api/v1/*.json`/`.yaml`, `llms.txt`, `llms-full.txt`, `badge-*.json` |
| `repo_click` | `location` (`header`, `footer`, `contribute`, `content`) | a link to this project's GitHub repository (`github.com/pacocartones/free-llm-api-hub`, any path) is clicked or middle-clicked. `location` is the link's `data-repo-location` when it names one from the list; else `header` or `footer` when the link sits in the site header or footer (the Star on GitHub buttons); else `contribute` on `/contributing/` and `/submit/` or for issue forms, discussions, pull requests, forks and `CONTRIBUTING.md`; else `content` |
| `site_search` | `search_term` (lower-case, max. 60 characters) | the explorer search box, after 1.5 s without typing, on Enter or when it loses focus; an identical consecutive query is sent once |
| `wizard_complete` | `use` (`any`, `chat`, `code`, `embeddings`, `speech`, `image`, `ocr`), `filters` (a comma list from `card`, `phone`, `commercial`, `train`, `openai`, or `none`), `result_count` (0–999) | `/find/` finishes the questions (Next on the last one, or Skip to results); `site/find.js` dispatches a `fllm:wizard-complete` DOM event and `consent.js` validates and sends it. A shared results link does not count. |

In the GA4 stream, enhanced measurement keeps page views on real loads, scrolls, outbound clicks and file downloads. Its "page changes based on browser history events" and "site search" options are **off**: the explorer rewrites its URL with `history.replaceState` on every keystroke, so they would send one page view or search per key. `site_search` replaces that. The custom events add the provider-specific detail under their own names; they do not replace GA's automatic outbound-click and file-download events.

**Mark as key events in GA4:** `outbound_provider_click` (a visitor leaves for a provider, the site's main outcome), `copy_snippet` (a visitor takes code to use a provider) and `api_download` (dataset or API reuse). `repo_click` measures the path to stars and contributions; mark it too if repository growth is a goal. The others are for understanding behaviour, not outcomes.
