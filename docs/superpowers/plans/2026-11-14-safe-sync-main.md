# Safe Sync Main Implementation Plan

> **Status (2026-11-14): Executed.** The implementation is in PR #593. Every checked step below was completed; the focused Windows suite was subsequently optimized from 800–934 seconds to 16 seconds by retaining two real CLI acceptance paths and moving fault/configuration matrices to an isolated deterministic runner around the real coordinator.

**Execution note:** The final performance pass supersedes the plan's per-case real-repository wording for matrix tests. Real Git still proves the generated-only fixture and drives the success/source-conflict CLI acceptances. Configuration, preflight, literal-path, fault, mode, ownership and recovery matrices exercise `syncMain` itself through its command seam with isolated temporary worktrees and explicit command/state assertions. This preserves each trust-boundary case without recreating and cloning repositories for equivalent scenarios.

**Goal:** Add `npm run sync-main` to merge fetched `origin/main`, rebuild conflicts confined to the shared generated targets, and abort safely when any other path conflicts.

**Architecture:** Keep a small Node CLI and importable coordinator in `scripts/sync-main.mjs`, with temporary-repository integration tests in `scripts/sync-main.test.mjs`. Freeze the generated-path policy imported from `generated-targets.mjs` before merging, expand its directory target to exact indexed paths, and use Git's NUL-delimited interfaces and literal pathspecs throughout. Leave OG resolution manual; merge commits preserve both parents and the command never pushes.

**Tech Stack:** Node.js `>=18`, ES modules, `node:test`, Node built-ins, Git; no new dependencies.

**Spec:** [GitHub issue #569](https://github.com/pacocartones/free-llm-api-hub/issues/569), read on 2026-11-14 (open, zero comments), with conservative decisions and failure contracts recorded below. Read `scripts/generated-targets.mjs`, `scripts/generated-targets.test.mjs`, `scripts/check-generated.mjs`, `scripts/check-og.mjs`, `scripts/build.mjs`, `CONTRIBUTING.md`, and `.github/workflows/verify.yml` before implementing.

## Global Constraints

- “checks that the working tree is clean” — include staged, unstaged and non-ignored untracked files, and refuse an existing Git operation before fetching.
- “runs `git fetch` and merges `origin/main`” — fetch the named branch without force and pin the resulting commit before merging.
- “if **only** files in the generated list conflict” — inspect the entire unmerged index before any automatic resolution or build.
- “if any **other** file conflicts, runs `git merge --abort` and stops, saying which files conflict; afterwards `git status` is the same as before you started.”
- “Reuse `scripts/generated-targets.mjs`” — import `generatedTargets`, `STATIC_TARGETS`, `isGenerated` and `parseNul`; do not duplicate the target/exclusion lists or change drift-gate semantics.
- “Use `--theirs` only on paths of the list, by exact path or by directory (`collections/`), never by a loose pattern.” Expand `collections/` to concrete paths and pass each with literal pathspec semantics.
- “Compatible with Node `>=18`. Never force, never rewrite history, never push.” No rebase, reset, amend, clean, stash/autostash, `git add .`, `git add -A` without explicit paths, or forced fetch/ref update.
- Tests must first prove their fixture really produces the intended conflicts. All Git writes during tests stay inside disposable repositories and local bare remotes.
- Execution was explicitly authorized after this plan was reviewed. The helper itself still never pushes or mutates GitHub state.

## Review Focus

1. Path names with spaces, Unicode, brackets or Git pathspec syntax must remain individual literal paths; no matching sibling may be overwritten (Tasks 1 and 3).
2. Existing staged/unstaged/untracked work, detached HEAD, shallow history and an existing merge/rebase must stop the helper before fetch or build (Task 2).
3. A mixed generated/source conflict, including `site/og/manifest.json` or a handwritten site asset, must abort before any checkout/build and restore the original HEAD, index and porcelain status (Task 2).
4. Failed fetch/build/staging/commit or abort must not be mistaken for success, delete unrelated files, or trigger history rewriting; cleanup failures must retain actionable state (Tasks 2 and 4).
5. A build that writes the date-relative `badge-freshness.json`, a new generated page, or an unexpected source file must not cause broad staging or discard a legitimate incoming source change (Task 3).

## Decisions and existing behavior

- **OG decision:** leave `site/og/*`, `site/og.png` and `site/og.svg` outside automatic resolution and staging. They are excluded by the shared list; `og.svg` is a handwritten template, and image rendering has a separate native development dependency. Any OG conflict takes the non-generated abort path. On a successful sync, print: `OG files were not regenerated. Run node scripts/check-og.mjs; if it reports drift, run npm run og and commit the resulting OG files yourself.` Do not run `og` or silently add its outputs. Record this choice in the eventual issue/PR explanation only when such publication is separately authorized.
- **Build execution:** invoke `process.execPath` with the repository's `scripts/build.mjs`, the exact entrypoint currently used by `npm run build`. This is portable on Windows and Node 18, avoids launching `npm.cmd` through a shell, and avoids incidental npm lifecycle hooks. A package contract test pins `scripts.build === 'node scripts/build.mjs'`; if that script changes later, update this decision deliberately.
- **Conflict policy versus staging:** the frozen shared policy authorizes generated paths, not arbitrary files underneath `site/`. `collections` is the sole directory target today; match `collections/` at a path-component boundary, never `collections-extra/`. Evaluate the full unmerged index, including delete/modify paths, before touching any path. Use current index candidates to include both sides' tracked additions; never execute or reload a policy file changed by the merge to widen permission midway through the operation.
- **Normal Git cases:** an already-contained target is a successful no-op. A fast-forward is a normal fast-forward with no extra commit or build. A clean divergent merge is committed normally without automatic regeneration; this helper's rebuild path addresses generated conflicts, and users still run the required checks before submitting. A divergent merge with exclusively generated conflicts resolves those conflicts, rebuilds, stages exact generated outputs and makes one merge commit.
- **Source and generated output coexist:** ordinary non-conflicting incoming changes to `data/`, `scripts/`, `docs/`, and assets remain in Git's merge index and must be included in the merge commit. They are not authorized automatic conflict resolutions. `README.md` and `docs/credit-programs.md` contain some handwritten content but are explicitly shared targets, so whole-file `--theirs` follows the issue's existing contract; do not broaden that contract to other docs.
- **Freshness badge:** `scripts/build.mjs` also rewrites tracked `badge-freshness.json`, which is intentionally excluded from `STATIC_TARGETS`. After generated conflicts have been resolved and staged, capture the pre-build index tree with `git write-tree`. Restore only this known excluded build side effect from that tree to the worktree, leaving its already-merged index version intact. Do not add the badge to the shared list or silently restore every unexpected build write.
- **Status promise:** compare `git status --porcelain=v1 -z --untracked-files=all --ignore-submodules=none`, the initial HEAD and branch, not human-readable upstream ahead/behind prose. Fetch necessarily updates remote metadata and `FETCH_HEAD`; the source-conflict abort restores the local worktree/index/HEAD. Ignored preview files are outside this status contract and must never be broadly deleted.
- **Trust boundary:** this is a local helper for a repository the contributor trusts. Fetch uses the contributor's configured `origin`; it does not discover another upstream or accept arbitrary remote/ref arguments. Running the merged build and normal Git hooks executes repository/local code; the helper is not a sandbox and must not be installed as a privileged workflow for untrusted PRs. No workflow permissions or credentials change.
- **Observed Git fixture proof:** a disposable-repository experiment on Git 2.56.0.windows.4 confirmed that edits to well-separated provider rows merge cleanly while competing one-line `derived-fingerprints.json` edits yield merge exit 1 and exactly that unmerged path. Stage 3 contained main's bytes, stage 2 the feature's bytes; `git merge --abort` restored the original HEAD and empty porcelain status. Reproduce that proof inside the tests rather than relying on this experiment.
