# Static JSON API: stability and versioning

The [static JSON API](https://freellmapihub.com/api/) serves the dataset as files under `/api/v1/`. There is no server behind it: every file is generated by `scripts/build.mjs` from [`data/providers.json`](../data/providers.json) and [`data/programs.json`](../data/programs.json) and redeployed on every dataset change. This page says what a consumer can rely on.

## What `/api/v1/` guarantees

1. **Paths are stable within v1.** A file listed in [`/api/v1/index.json`](https://freellmapihub.com/api/v1/index.json) under `endpoints` keeps its path for as long as v1 is served. New files may be added, and are added to `endpoints` when they are.
2. **Fields are only added within v1.** A field present in a v1 response is never renamed, removed, or given a different type or meaning while v1 is served. New fields can appear at any time, so parse leniently: ignore keys you do not know.
3. **Values change; shapes do not.** The data itself (limits, flags, model samples, counts) changes with every re-verification. That is the point of the dataset, not a breaking change. A provider can also leave the dataset when its free tier ends; its `slug` is never reused for a different provider.
4. **A breaking change ships as `/api/v2/`.** Renaming or removing a field, changing a type, or changing what a value means goes to a new path. `/api/v1/` keeps being generated, from the same data, for a deprecation period announced in the [changelog](../CHANGELOG.md) and on the API page when `/api/v2/` is published.

**One removal, on record.** The schema published at [`/api/v1/schema.json`](https://freellmapihub.com/api/v1/schema.json) declared two optional provider properties, `partner` and `partner_note`, from dataset 2.11.0 (13 October 2026). They are removed from the schema on 2026-10-16. No response of `/api/v1/` ever carried either one (no provider had a value for them), so no value a client could read changes; what changes is that the published schema loses those two property names, and the `intro` text of `/api/v1/best.json` now says that money, not only a partnership, adds nothing to the score. This is a withdrawal from a published schema, not an addition, and it is recorded here and in the [changelog](../CHANGELOG.md) so that the rules above are not read as saying that nothing was ever removed.

What is *not* guaranteed: the order of providers in a list, the exact contents of sampled fields such as `models_free`, and the human-facing HTML pages.

### Fields added within v1

- **`no_expiry`** (dataset 2.10.0): an optional object on one-time trial credits whose provider says the credit does not expire — `source`, `checked`, `quote`. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected. `expires` keeps its type and meaning (a window such as `"30 days"`, or `null`).
- **`data_policy`** (dataset 2.11.0): an optional object with `trains_on_prompts` (boolean or `null`), `retention` (string or `null`), `source`, `checked`, and an optional `plan_named` (boolean or `null`): whether the sentence names the free or trial plan: `true` = it does, to cover or to exclude it; `false` = the source was read and does not name it in that sentence (never that the plan is covered, nor that it is not); `null` or absent = not checked. Absent or `null` means nobody has recorded it. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected.
- **`model_tier` / `model_tier_source`** (dataset 2.10.0): optional `model_tier` integer from 0 to 4, with `model_tier_source` an optional object containing the provider's model, the exact LMArena row it maps to, that row's rating, its two-number 95% confidence interval `ci`, votes, snapshot date, and `boundary` (boolean): whether the interval crosses or approaches a tier threshold. `model_tier` and `model_tier_source` are `null` or absent when there is no public rating source; `model_tier_source` is present if and only if `model_tier` is. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected.
- **`free_limits`** (dataset 2.10.0): an optional object with optional positive-integer `requests_per_second/minute/day/month` and `tokens_per_day/month` limits as published by the provider, an optional `scope`, and required `source` (an HTTP(S) URL) and `checked` (a date). An omitted limit field means no value is recorded for that unit; `null` or absent for the object means the provider publishes no numeric free limits. Numbers are never converted between units. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected.
- **`commercial_ok_condition`** (dataset 2.12.0): an optional string explaining the conditions when commercial use is conditional (e.g. per-model licences or give-back rules). In `/api/v1/` responses, `commercial_ok` remains `null` for such providers to preserve the `boolean | null` type contract, while `commercial_ok_condition` carries the reason. Consumers that ignore unknown fields are unaffected.

### The score: `/api/v1/score.json`

[`/api/v1/score.json`](https://freellmapihub.com/api/v1/score.json) is the whole [FLLMAPIHUB score](methodology.md#the-score), not only the top 10 that [`best.json`](https://freellmapihub.com/api/v1/best.json) carries. It lists every eligible provider (verified and inside the freshness window), best score first, with the parts of the score and how many of its inputs the data confirms. The numbers are the same as in `best.json` (one rounding rule, one source), and the file is byte-stable for a given dataset: the scores are computed at `generated`.

Its contract is **v1** and is described by a JSON Schema at a stable URL, [`/api/v1/score.schema.json`](https://freellmapihub.com/api/v1/score.schema.json) (the source is [`data/score.schema.json`](../data/score.schema.json)). The file names it in `schema`. The rules above apply: a field named below is never renamed, removed or retyped within v1, new fields may be added, so read only the fields you need and ignore the rest; a breaking change goes to `/api/v2/`.

Top level:

| Field | Type | Meaning |
|---|---|---|
| `dataset`, `version`, `generated`, `license`, `homepage`, `docs`, `description` | | the same envelope as every other file of the API |
| `schema` | URL | the URL of the JSON Schema of this file |
| `method` | URL | the public page that explains how the score works |
| `weights` | object | the points each part can add (`quality`, `limits`, `friction`, `commercial`, `openai`, `stability`, `editorial`), out of 100 in total |
| `editorial_default` | integer | the editorial points a provider gets without a rating of its own |
| `editorial_neutral` | boolean | true while every provider carries that default, so the editorial part moves no position |
| `min_confirmed` | integer | how many of the mathematical inputs must be confirmed to enter the top |
| `top_size`, `podium_size` | integer | the most providers the top holds, and how many form the podium |
| `count` | integer | the number of providers listed |
| `providers` | array | one object per eligible provider, as below |

Each object of `providers`:

| Field | Type | Meaning |
|---|---|---|
| `slug`, `name` | string | the provider |
| `is_text_llm` | boolean | whether the free access gives text-LLM API access, which the top requires |
| `score` | number | the total out of 100, one decimal |
| `math`, `editorial` | number | the mathematical points and the editorial points after the cap, one decimal |
| `confirmed`, `of` | integer | how many of the mathematical inputs the data confirms, out of how many exist |
| `parts` | object | the points of each mathematical input (`quality`, `limits`, `friction`, `commercial`, `openai`, `stability`), one decimal |
| `meets_minimum` | boolean | true when `confirmed` reaches `min_confirmed` |
| `in_top` | boolean | true when the provider is in the top |
| `top_rank` | integer or null | its place in the top, or `null` |
| `tier_near_threshold` | boolean | true when the model-quality tier is near a threshold and could change at the next snapshot; the score keeps it as it is |

A provider with few confirmed inputs still appears, with a low `confirmed`: missing information scores zero or neutral and is never estimated. A provider that is not verified, or is past the freshness window, is not listed. Nothing paid is in these files: the agreements are a file apart, `data/sponsorships.json`, which is not published under `/api/v1/`.

```json
{
  "dataset": "free-llm-api-hub",
  "schema": "https://freellmapihub.com/api/v1/score.schema.json",
  "min_confirmed": 4,
  "providers": [
    { "slug": "example", "name": "Example", "is_text_llm": true, "score": 67.2, "math": 52.2, "editorial": 15, "confirmed": 5, "of": 6,
      "parts": { "quality": 22, "limits": 4.2, "friction": 13, "commercial": 9, "openai": 4, "stability": 0 },
      "meets_minimum": true, "in_top": true, "top_rank": 1, "tier_near_threshold": false }
  ]
}
```

(abridged: the real file carries every field of the tables above.)

### Free GPU compute: `/api/v1/free-gpu.json`

[`/api/v1/free-gpu.json`](https://freellmapihub.com/api/v1/free-gpu.json) is the [Free GPU compute](https://freellmapihub.com/free-gpu/) section as data: services that give free GPU time, **apart from the provider ranking**. It is not a list of providers and it carries no count of providers: nothing in it enters `providers.json`, a slice, a collection or the score. Each value rests on a sentence from the service's own page and the day it was read; a value the page did not state is `not_stated` and is never filled in.

Its contract is **v1** and is described by a JSON Schema at a stable URL, [`/api/v1/free-gpu.schema.json`](https://freellmapihub.com/api/v1/free-gpu.schema.json) (the source is [`data/free-gpu.schema.json`](../data/free-gpu.schema.json)). The file names it in `schema`. The rules above apply: a field named below is never renamed, removed or retyped within v1, new fields may be added, so read only the fields you need and ignore the rest.

| Field | Type | Meaning |
|---|---|---|
| `schema` | URL | the schema of this file |
| `page` | URL | the public page that shows the same section |
| `count` | integer | the number of `entries`; not a count of providers |
| `entries` | array | the services, in the order of the data file |
| `notes` | array | services worth knowing about that are not entries, such as a free trial that does not allow GPUs |

Each entry has:

| Field | Type | Meaning |
|---|---|---|
| `slug` | string | the identifier; never the slug of a provider of the dataset |
| `name` | string | the display name |
| `url` | URL | the service's own page |
| `kind` | string | `notebook` or `serverless-api` |
| `claims` | object | `gpu_access`, `quota`, `credit_amount`, `expires` and `card_required`, each a claim |

A claim has `state`, which is `stated` or `not_stated`, and `quotes`, a list of quotations. A `stated` claim has at least one quotation; a `not_stated` claim may carry the sentences that do not settle it, such as two expiry sentences that disagree. A quotation has `text`, the sentence as the page words it, `source`, the service's own page, and `read`, the day it was read. A note has `subject`, `text` and `quotes`.

### Free AI coding tools you connect your own key to: `/api/v1/coding-tools-own-key.json`

[`/api/v1/coding-tools-own-key.json`](https://freellmapihub.com/api/v1/coding-tools-own-key.json) is the second part of the [Free AI coding tools](https://freellmapihub.com/coding-tools/#own-key) section as data: tools that are free themselves while inference is paid with your own key or a free API, **apart from the provider ranking** and from the tools that bring their own free plan. It is a file of its own so the contract of `coding-tools.json` never changes and the two lists never mix in a client. It has the same shape, the same rules (a `stated` value rests on a sentence of the tool's own page, `not_stated` is never `no`) and the same fields as `coding-tools.json`, described above; its JSON Schema is [`/api/v1/coding-tools-own-key.schema.json`](https://freellmapihub.com/api/v1/coding-tools-own-key.schema.json) (the source is [`data/coding-tools-own-key-api.schema.json`](../data/coding-tools-own-key-api.schema.json)). It carries no count of providers and nothing in it enters `providers.json`, a slice, a collection or the score.

### Generated client configs

`/api/v1/openai-clients.json` and `/api/v1/litellm.yaml` follow the same rules. Their *contents* follow the data: a provider enters or leaves them when it becomes, or stops being, verified and OpenAI-compatible with a known base URL and key variable. They carry `env_key`, the **name** of the environment variable for your own API key (for example `GROQ_API_KEY`), never a key value. The other API files do not carry `env_key`.

## `version` in the data and the API path

Every API object carries `version` and `generated`, copied from `data/providers.json`:

- **`version`** is the dataset's [SemVer](https://semver.org/) release version, in lockstep with the `vX.Y.Z` Git tag (it is not a separate schema version). Minor and patch bumps are additive: a new field, a new file, a re-verification release. They stay on `/api/v1/`.
- **A new major `version`** is reserved for a breaking change to the shape, and is the release that introduces the next API path. The API path counts breaking changes to the API; it does not repeat the dataset's major number.
- **`generated`** is the date of the last dataset change (`YYYY-MM-DD`). Generated files are byte-stable for a given dataset: nothing in them depends on the day the build ran.

The JSON Schema the dataset is validated against is published at [`/api/v1/schema.json`](https://freellmapihub.com/api/v1/schema.json), a byte-for-byte copy of [`data/schema.json`](../data/schema.json).

## Pinning a snapshot

The live API always serves the latest data. To pin one, use a Git tag: when `version` in `data/providers.json` advances on `main`, the `tag-release.yml` workflow creates the annotated tag `vX.Y.Z` for it. A tag pins the whole repository, data and generator included, so you can either read `data/providers.json` at that tag:

```bash
curl -s https://raw.githubusercontent.com/pacocartones/free-llm-api-hub/v2.9.1/data/providers.json
```

or check the tag out and run `npm ci --ignore-scripts && npm run build` to regenerate the exact `/api/v1/` files of that release under `site/api/v1/`.
