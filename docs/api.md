# Static JSON API: stability and versioning

The [static JSON API](https://freellmapihub.com/api/) serves the dataset as files under `/api/v1/`. There is no server behind it: every file is generated by `scripts/build.mjs` from [`data/providers.json`](../data/providers.json) and [`data/programs.json`](../data/programs.json) and redeployed on every dataset change. This page says what a consumer can rely on.

### Ongoing free tiers that need no card ([`providers.json`](https://freellmapihub.com/api/v1/providers.json))

Free tiers that renew (`category` is `ongoing`) where the provider confirms no payment card is needed. `card_required` is `true`, `false` or `null`; `null` means not confirmed, so test for `false`, never for a falsy value.

curl:

```bash
curl -fsS https://freellmapihub.com/api/v1/providers.json \
  | jq -r '.providers[] | select(.category == "ongoing" and .card_required == false) | "\(.slug)\t\(.name)"'
```

JavaScript (fetch, no dependencies):

```js
const res = await fetch("https://freellmapihub.com/api/v1/providers.json");
const { providers } = await res.json();
for (const p of providers) {
  if (p.category === "ongoing" && p.card_required === false) console.log(`${p.slug}\t${p.name}`);
}
```

Python (standard library only):

```python
import json, urllib.request

with urllib.request.urlopen("https://freellmapihub.com/api/v1/providers.json") as res:
    providers = json.load(res)["providers"]
for p in providers:
    if p["category"] == "ongoing" and p["card_required"] is False:
        print(f"{p['slug']}\t{p['name']}")
```

### Providers whose data is fresh and free now ([`status.json`](https://freellmapihub.com/api/v1/status.json))

The small file to poll. `freshness` is graded against the SLA at `generated_at`; `free_now` is `true` only for a verified entry whose last probe did not report the free tier gone. It is not a live check of the provider.

curl:

```bash
curl -fsS https://freellmapihub.com/api/v1/status.json \
  | jq -r '.providers | to_entries[] | select(.value.freshness == "fresh" and .value.free_now == true) | "\(.key)\t\(.value.last_verified)"'
```

JavaScript (fetch, no dependencies):

```js
const res = await fetch("https://freellmapihub.com/api/v1/status.json");
const status = await res.json();
for (const [slug, s] of Object.entries(status.providers)) {
  if (s.freshness === "fresh" && s.free_now === true) console.log(`${slug}\t${s.last_verified}`);
}
```

Python (standard library only):

```python
import json, urllib.request

with urllib.request.urlopen("https://freellmapihub.com/api/v1/status.json") as res:
    status = json.load(res)
for slug, s in status["providers"].items():
    if s["freshness"] == "fresh" and s["free_now"] is True:
        print(f"{slug}\t{s['last_verified']}")
```

### The provider with the highest daily request limit for a model ([`providers.json`](https://freellmapihub.com/api/v1/providers.json))

`free_limits` holds the numeric limits the provider publishes, never converted between units; an omitted unit means no value is recorded. Model ids in `models_free` are a sample and may carry a vendor prefix (`openai/gpt-oss-120b`), so the match accepts one.

curl:

```bash
curl -fsS https://freellmapihub.com/api/v1/providers.json \
  | jq -r --arg m gpt-oss-120b '[.providers[]
      | select(.free_limits.requests_per_day != null and any(.models_free[]?; . == $m or endswith("/" + $m)))]
    | max_by(.free_limits.requests_per_day)
    | if . == null then "no provider publishes a daily request limit for \($m)"
      else "\(.slug)\t\(.free_limits.requests_per_day)" end'
```

JavaScript (fetch, no dependencies):

```js
const MODEL = "gpt-oss-120b";
const res = await fetch("https://freellmapihub.com/api/v1/providers.json");
const { providers } = await res.json();
let best = null;
for (const p of providers) {
  const rpd = p.free_limits?.requests_per_day;
  const serves = (p.models_free ?? []).some((m) => m === MODEL || m.endsWith("/" + MODEL));
  if (rpd != null && serves && (!best || rpd > best.free_limits.requests_per_day)) best = p;
}
console.log(best ? `${best.slug}\t${best.free_limits.requests_per_day}` : `no provider publishes a daily request limit for ${MODEL}`);
```

Python (standard library only):

```python
import json, urllib.request

MODEL = "gpt-oss-120b"
with urllib.request.urlopen("https://freellmapihub.com/api/v1/providers.json") as res:
    providers = json.load(res)["providers"]
best = None
for p in providers:
    rpd = (p.get("free_limits") or {}).get("requests_per_day")
    serves = any(m == MODEL or m.endswith("/" + MODEL) for m in p.get("models_free") or [])
    if rpd is not None and serves and (best is None or rpd > best["free_limits"]["requests_per_day"]):
        best = p
print(f"{best['slug']}\t{best['free_limits']['requests_per_day']}" if best else f"no provider publishes a daily request limit for {MODEL}")
```

### No card and commercial use allowed, from the CSV ([`providers.csv`](https://freellmapihub.com/providers.csv))

The CSV keeps `true`, `false` and `conditional` as words; an empty cell means unknown, never `false`. Text cells can hold commas, quotes and line breaks, so use a real CSV parser (JavaScript has none built in; the eight-line one below handles quoted cells). With curl, download the file and open it in a spreadsheet.

curl:

```bash
curl -fsS -o providers.csv https://freellmapihub.com/providers.csv
head -n 1 providers.csv | tr ',' '\n'
```

JavaScript (fetch, no dependencies):

```js
const res = await fetch("https://freellmapihub.com/providers.csv");
const text = await res.text();
const rows = [];
let row = [], cell = "", quoted = false;
for (let i = 0; i < text.length; i++) {
  const c = text[i];
  if (quoted) { if (c === '"' && text[i + 1] === '"') { cell += '"'; i++; } else if (c === '"') quoted = false; else cell += c; }
  else if (c === '"') quoted = true;
  else if (c === ",") { row.push(cell); cell = ""; }
  else if (c === "\n") { row.push(cell); rows.push(row); row = []; cell = ""; }
  else if (c !== "\r") cell += c;
}
if (cell || row.length) { row.push(cell); rows.push(row); }
const [header, ...data] = rows;
for (const values of data) {
  const r = Object.fromEntries(header.map((h, i) => [h, values[i]]));
  if (r.card_required === "false" && r.commercial_ok === "true") console.log(`${r.slug}\t${r.name}`);
}
```

Python (standard library only):

```python
import csv, io, urllib.request

with urllib.request.urlopen("https://freellmapihub.com/providers.csv") as res:
    rows = list(csv.DictReader(io.TextIOWrapper(res, encoding="utf-8", newline="")))
for r in rows:
    if r["card_required"] == "false" and r["commercial_ok"] == "true":
        print(f"{r['slug']}\t{r['name']}")
```

### Every provider’s Markdown page, from llms.txt ([`llms.txt`](https://freellmapihub.com/llms.txt))

`llms.txt` is the index for agents: under `## Providers` each line links the provider page and its Markdown twin (`/p/<slug>.md`), which is the cheapest thing to put in a model’s context.

curl:

```bash
curl -fsS https://freellmapihub.com/llms.txt \
  | awk '/^## /{p = ($0 == "## Providers")} p' \
  | grep -oE '\(https://[^)]+\.md\)' | tr -d '()'
```

JavaScript (fetch, no dependencies):

```js
const res = await fetch("https://freellmapihub.com/llms.txt");
let section = "";
for (const line of (await res.text()).split("\n")) {
  if (line.startsWith("## ")) section = line;
  const md = line.match(/\((https:\/\/[^)]+\.md)\)/);
  if (section === "## Providers" && md) console.log(md[1]);
}
```

Python (standard library only):

```python
import re, urllib.request

with urllib.request.urlopen("https://freellmapihub.com/llms.txt") as res:
    text = res.read().decode("utf-8")
section = ""
for line in text.split("\n"):
    if line.startswith("## "):
        section = line
    md = re.search(r"\((https://[^)]+\.md)\)", line)
    if section == "## Providers" and md:
        print(md.group(1))
```

## Spreadsheet subset: `/providers.csv`

[`/providers.csv`](https://freellmapihub.com/providers.csv) is a generated scalar projection for spreadsheet import. [`/api/v1/providers.json`](https://freellmapihub.com/api/v1/providers.json) remains the complete representation. The CSV is generated by `scripts/build.mjs` from the same public provider projection as the JSON: one row per provider, keyed by `slug`, including unverified entries, and every row repeats `dataset_version` and `dataset_generated` from `data/providers.json`.

Columns, in order:

`dataset_version`, `dataset_generated`, `slug`, `name`, `category`, `free_type`, `free_tier`, `rate_limits`, `notes`, `best_for`, `expires`, `docs_url`, `models_url`, `phone_required`, `card_required`, `commercial_ok`, `commercial_ok_condition`, `openai_compatible`, `openai_base_url`, `is_text_llm`, `model_tier`, `verified`, `last_verified`, `added`, `last_probed`, `probe_status`

The values `true`, `false`, and `conditional` stay as those words. For a conditional answer, `commercial_ok_condition` carries the documented reason in its own column. An empty cell means `null`, absent, or not stated; it never means `false` or `0`. To prevent spreadsheet formula execution, a string cell whose first non-whitespace character is `=`, `+`, `-`, or `@` gets a leading apostrophe before CSV quoting; numbers, booleans and empty cells keep their normal representation. Text is UTF-8 CSV, with commas, quotes and line breaks quoted as CSV requires.

These fields are omitted because they are arrays, nested objects, or operational details, and flattening them would hide conditions or provenance: `modalities`, `models_free`, `model_tier_source`, `free_limits`, `no_expiry`, `anonymous_access`, `data_policy`, `field_checks`, `published_speed`, `env_key`, and the optional link fields `playground_url`, `keys_url` and `keys_url_source`.

## What `/api/v1/` guarantees

1. **Paths are stable within v1.** A file listed in [`/api/v1/index.json`](https://freellmapihub.com/api/v1/index.json) under `endpoints` keeps its path for as long as v1 is served. New files may be added, and are added to `endpoints` when they are.
2. **Fields are only added within v1.** A field present in a v1 response is never renamed, removed, or given a different type or meaning while v1 is served. New fields can appear at any time, so parse leniently: ignore keys you do not know. The published [`/api/v1/schema.json`](https://freellmapihub.com/api/v1/schema.json) follows the same rule: from dataset 2.15.0 its objects set `additionalProperties: true`, so a strict validator accepts a key the schema does not list yet (see [`version` in the data and the API path](#version-in-the-data-and-the-api-path) below).
3. **Values change; shapes do not.** The data itself (limits, flags, model samples, counts) changes with every re-verification. That is the point of the dataset, not a breaking change. A provider can also leave the dataset when its free tier ends; its `slug` is never reused for a different provider.
4. **A breaking change ships as `/api/v2/`.** Renaming or removing a field, changing a type, or changing what a value means goes to a new path. `/api/v1/` keeps being generated, from the same data, for a deprecation period announced in the [changelog](../CHANGELOG.md) and on the API page when `/api/v2/` is published.

**One removal, on record.** The schema published at [`/api/v1/schema.json`](https://freellmapihub.com/api/v1/schema.json) declared two optional provider properties, `partner` and `partner_note`, from dataset 2.11.0 (13 October 2026). They are removed from the schema on 2026-10-16. No response of `/api/v1/` ever carried either one (no provider had a value for them), so no value a client could read changes; what changes is that the published schema loses those two property names, and the `intro` text of `/api/v1/best.json` now says that money, not only a partnership, adds nothing to the score. This is a withdrawal from a published schema, not an addition, and it is recorded here and in the [changelog](../CHANGELOG.md) so that the rules above are not read as saying that nothing was ever removed.

What is *not* guaranteed: the order of providers in a list, the exact contents of sampled fields such as `models_free`, and the human-facing HTML pages.

### Fields added within v1

- **`free_limits.per_model`** (unreleased, planned for dataset 2.16.0): an optional array inside the existing `free_limits` object, for providers whose official page publishes limits per model. Each entry is `{ model, requests_per_second?, requests_per_minute?, requests_per_day?, requests_per_month?, tokens_per_day?, tokens_per_month?, scope? }`: `model` is an ID of the same provider's `models_free`, exactly as listed, appears once, and the entry carries at least one number (`scripts/validate.mjs` rejects anything else). The entries share the object's `source` and `checked`: one page, read on one day. A model with no entry falls back to the provider-wide numbers of the object, which keep their meaning; nothing is copied from another model. `free_limits` stays one object (its v1 type), so this is a new key, not a new shape. No provider carries it yet: it is filled only when an official page gives the numbers per model. The CSV does not carry it.
- **`published_speed`** (unreleased, planned for dataset 2.15.0): an optional array on a provider. Each entry is a speed figure the provider publishes on its own site for a model of its `models_free`: `{ model, metric, unit, value, qualifier, conditions, plan_named, source, checked, quote }`. `metric` is `output_tokens_per_second` (`unit` `tokens/s`) or `time_to_first_token_ms` (`unit` `ms`); `qualifier` is `exact`, `approx`, `at_least` or `up_to`, as the quote words it; `plan_named: false` means the page ties the figure to no plan, so it is not stated for the free tier. These are provider claims, not measurements: figures from different providers are not a like-for-like comparison. Absent means nothing published or recorded, never "slow". No existing field changes. The CSV does not carry it. As with `field_checks`, a client validating with a copy of the published schema from before dataset 2.15.0 (which set `additionalProperties: false`) would reject the new key; fetch the current schema, which allows additional properties, or parse leniently.
- **`field_checks`** (unreleased, planned for dataset 2.15.0): an optional object on a provider, keyed by tri-state flag (`phone_required`, `card_required`, `commercial_ok`, `openai_compatible`). Each entry is `{ status, checked, sources, quote?, note? }`: `status` is `stated` (an official page says it; the flag is known), `source_silent` (the provider's pages that should say it were read and do not), `needs_account` (only an account would tell) or `sources_disagree` (two official pages contradict each other; at least two `sources` and a `note`); `checked` is the date the pages were read; `sources` lists 1 to 4 HTTPS pages of the provider; `quote` is the provider's sentence (only with `stated`); `note` is plain text. A flag with no entry has no recorded check (`not_checked`), which never means "no". No existing field changes type or meaning: a flag with a reason is still `null`, and `null` still means "not stated". Because v1 projects `commercial_ok: "conditional"` to `null`, a v1 object can carry `commercial_ok: null` with `field_checks.commercial_ok.status: "stated"`; with `commercial_ok_condition` that marks a documented condition. The CSV does not carry it. As with `data_policy`, a client validating with a copy of the published schema from before dataset 2.15.0 (which set `additionalProperties: false`) would reject the new key; fetch the current schema, which allows additional properties, or parse leniently. [`/coverage/`](https://freellmapihub.com/coverage/) shows the counts by status.
- **`keys_url` / `keys_url_source`** (unreleased): two optional HTTPS strings, present together. `keys_url` is the provider's own page where a signed-up user creates an API key, exactly as the provider's docs link it; `keys_url_source` is that docs page. Omitted means unrecorded (never guessed); no new property is required and no existing field changes. A recorded value requires a non-empty `docs_url` and adds a "Get a free key" action on the provider page. Like `playground_url`, they are not CSV columns.
- **`playground_url`** (dataset 2.13.0): an optional HTTPS string pointing to a provider-owned no-code playground. Omitted means unrecorded; no new property is required. A recorded value requires a non-empty `docs_url` and adds a "Try it" action on the provider page. This additive v1 field does not extend the CSV projection; its columns remain the explicit list above.
- **`no_expiry`** (dataset 2.10.0): an optional object on one-time trial credits whose provider says the credit does not expire — `source`, `checked`, `quote`. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected. `expires` keeps its type and meaning (a window such as `"30 days"`, or `null`).
- **`anonymous_access`** (unreleased, planned for dataset 2.15.0): an optional object on providers whose own page says the API can be called with no account — `source`, `checked`, `quote` and an optional `note`. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected. Absent means the pages do not say so.
- **`data_policy`** (dataset 2.11.0): an optional object with `trains_on_prompts` (boolean or `null`), `retention` (string or `null`), `source`, `checked`, and an optional `plan_named` (boolean or `null`): whether the sentence names the free or trial plan: `true` = it does, to cover or to exclude it; `false` = the source was read and does not name it in that sentence (never that the plan is covered, nor that it is not); `null` or absent = not checked. Absent or `null` means nobody has recorded it. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected.
- **`model_tier` / `model_tier_source`** (dataset 2.10.0): optional `model_tier` integer from 0 to 4, with `model_tier_source` an optional object containing the provider's model, the exact LMArena row it maps to, that row's rating, its two-number 95% confidence interval `ci`, votes, snapshot date, and `boundary` (boolean): whether the interval crosses or approaches a tier threshold. `model_tier` and `model_tier_source` are `null` or absent when there is no public rating source; `model_tier_source` is present if and only if `model_tier` is. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected.
- **`free_limits`** (dataset 2.10.0): an optional object with optional positive-integer `requests_per_second/minute/day/month` and `tokens_per_day/month` limits as published by the provider, an optional `scope`, and required `source` (an HTTP(S) URL) and `checked` (a date). An omitted limit field means no value is recorded for that unit; `null` or absent for the object means the provider publishes no numeric free limits. Numbers are never converted between units. It appears in the provider objects the API serves; consumers that ignore unknown fields are unaffected.
- **`commercial_ok_condition`** (dataset 2.12.0): an optional string explaining provider conditions on commercial use. The canonical dataset uses `commercial_ok: "conditional"` with this field, but every `/api/v1/` provider object and every `commercial_ok` value in `changes.json` projects that value to `null`, preserving v1's `boolean | null` type. The condition string remains present, so consumers can distinguish a documented condition from a wholly unconfirmed answer without retyping the existing field.

### Provider status: `/api/v1/status.json`

[`/api/v1/status.json`](https://freellmapihub.com/api/v1/status.json) is a small freshness record per provider, keyed by `slug`, for clients that poll the dataset (API routers, key pools, dashboards) and only need to know how recent each entry is and whether its free access is in effect, without downloading and re-deriving the full provider objects. It lists every provider of `providers.json`, including unverified ones.

Its contract is **v1** and is described by a JSON Schema at a stable URL, [`/api/v1/status.schema.json`](https://freellmapihub.com/api/v1/status.schema.json) (the source is [`data/status.schema.json`](../data/status.schema.json)). The file names it in `schema`. The rules above apply: a field named below is never renamed, removed or retyped within v1, new fields may be added, so read only the fields you need and ignore the rest.

Every state is graded at `generated_at`, the date of the last dataset change, never the build clock, so the file is byte-stable for a given dataset and history. A client that wants the state for its own today regrades `last_verified` with the thresholds in `sla`. `last_change` is mined from the git history, like `changes.json` and `history.json`.

Top level:

| Field | Type | Meaning |
|---|---|---|
| `dataset`, `version`, `generated`, `license`, `homepage`, `docs`, `description` | | the same envelope as every other file of the API |
| `schema` | URL | the URL of the JSON Schema of this file |
| `schema_version` | integer | the contract version of this file, `1` for as long as `/api/v1/` is served |
| `generated_at` | date | the day every state is graded at (equal to `generated`) |
| `sla` | object | `due_after_days` (60) and `stale_after_days` (90): the freshness SLA, as in [methodology](methodology.md) and on [`/quality/`](https://freellmapihub.com/quality/) |
| `count` | integer | the number of providers, equal to the number of keys of `providers` |
| `providers` | object | one entry per provider, keyed by its `slug`, in slug order |

Each entry of `providers`:

| Field | Type | Meaning |
|---|---|---|
| `last_verified` | date or null | the day the entry was last verified against the provider's own docs; `null` if never |
| `oldest_field_check` | date or null | the oldest `checked` day among the entry's `field_checks`; `null` when it has none |
| `freshness` | string | `fresh` (verified at most `due_after_days` before `generated_at`), `due` (up to `stale_after_days`), `stale` (older: the SLA is breached) or `unverified` (never verified) |
| `free_now` | boolean or null | `true`: verified, and the last probe did not report the free tier gone; `false`: the last probe reported `tier-ended`; `null`: not verified, so not stated. It is not a live check |
| `last_change` | date or null | the day of the entry's newest field-level change, the changes of `changes.json` over the whole history rather than its last 12 weeks; `null` when none is recorded |

```json
{
  "dataset": "free-llm-api-hub",
  "schema": "https://freellmapihub.com/api/v1/status.schema.json",
  "schema_version": 1,
  "generated_at": "2026-11-26",
  "sla": { "due_after_days": 60, "stale_after_days": 90 },
  "count": 79,
  "providers": {
    "example": { "last_verified": "2026-11-20", "oldest_field_check": "2026-11-24", "freshness": "fresh", "free_now": true, "last_change": "2026-11-21" }
  }
}
```

(abridged: the real file carries the full envelope and every provider.)

### The score: `/api/v1/score.json`

[`/api/v1/score.json`](https://freellmapihub.com/api/v1/score.json) is the whole [FLLMAPIHUB score](methodology.md#the-score), not only the top 10 that [`best.json`](https://freellmapihub.com/api/v1/best.json) carries. It lists every eligible provider (verified and inside the freshness window), best score first, with the parts of the score and how many of its inputs the data confirms. The numbers are the same as in `best.json` (one rounding rule, one source), and the file is byte-stable for a given dataset: the scores are computed at `generated`.

Its contract is **v1** and is described by a JSON Schema at a stable URL, [`/api/v1/score.schema.json`](https://freellmapihub.com/api/v1/score.schema.json) (the source is [`data/score.schema.json`](../data/score.schema.json)). The file names it in `schema`. The rules above apply: a field named below is never renamed, removed or retyped within v1, new fields may be added, so read only the fields you need and ignore the rest; a breaking change goes to `/api/v2/`.

Top level:

| Field | Type | Meaning |
|---|---|---|
| `dataset`, `version`, `generated`, `license`, `homepage`, `docs`, `description` | | the same envelope as every other file of the API |
| `schema` | URL | the URL of the JSON Schema of this file |
| `method` | URL | the public page that explains how the score works |
| `weights` | object | the points each part can add (`quality`, `limits`, `friction`, `commercial`, `openai`, `stability`, `editorial`), out of 100 in total |
| `editorial_default` | integer | the editorial points a provider gets without a rating of its own |
| `editorial_neutral` | boolean | true while every provider carries that default, so the editorial part moves no position |
| `min_confirmed` | integer | how many of the mathematical inputs must be confirmed to enter the top |
| `top_size`, `podium_size` | integer | the most providers the top holds, and how many form the podium |
| `count` | integer | the number of providers listed |
| `providers` | array | one object per eligible provider, as below |

Each object of `providers`:

| Field | Type | Meaning |
|---|---|---|
| `slug`, `name` | string | the provider |
| `is_text_llm` | boolean | whether the free access gives text-LLM API access, which the top requires |
| `score` | number | the total out of 100, one decimal |
| `math`, `editorial` | number | the mathematical points and the editorial points after the cap, one decimal |
| `confirmed`, `of` | integer | how many of the mathematical inputs the data confirms, out of how many exist |
| `parts` | object | the points of each mathematical input (`quality`, `limits`, `friction`, `commercial`, `openai`, `stability`), one decimal |
| `meets_minimum` | boolean | true when `confirmed` reaches `min_confirmed` |
| `in_top` | boolean | true when the provider is in the top |
| `top_rank` | integer or null | its place in the top, or `null` |
| `tier_near_threshold` | boolean | true when the model-quality tier is near a threshold and could change at the next snapshot; the score keeps it as it is |

A provider with few confirmed inputs still appears, with a low `confirmed`: missing information scores zero or neutral and is never estimated. A provider that is not verified, or is past the freshness window, is not listed. Nothing paid is in these files: the agreements are a file apart, `data/sponsorships.json`, which is not published under `/api/v1/`.

```json
{
  "dataset": "free-llm-api-hub",
  "schema": "https://freellmapihub.com/api/v1/score.schema.json",
  "min_confirmed": 4,
  "providers": [
    { "slug": "example", "name": "Example", "is_text_llm": true, "score": 67.2, "math": 52.2, "editorial": 15, "confirmed": 5, "of": 6,
      "parts": { "quality": 22, "limits": 4.2, "friction": 13, "commercial": 9, "openai": 4, "stability": 0 },
      "meets_minimum": true, "in_top": true, "top_rank": 1, "tier_near_threshold": false }
  ]
}
```

### The free-model matrix: `/api/v1/models.json`

[`/api/v1/models.json`](https://freellmapihub.com/api/v1/models.json) (unreleased, planned for dataset 2.16.0) answers "which free APIs list this model?" for every model at once: one record per model, with one row per provider that lists it in its free-model sample (`models_free`). The models are the same groups, under the same keys, as the [model pages](https://freellmapihub.com/models/) `/models/<key>/`: an ID loses its deployment prefix (`@cf/`), its organisation prefix and OpenRouter's `:free` suffix and is lower-cased; a different size, version, date or suffix stays a different model, and any other merge needs a reviewed alias. An ID that gives no valid key is not in the file (it has no page either). When one provider lists two IDs with the same key, the row carries the first one.

Every value is a field of `data/providers.json` that is already recorded, projected to the v1 types (`commercial_ok` is `boolean | null`, as in every v1 provider object). `null` means not recorded or not confirmed, never "no", and nothing is estimated. Model lists are a sample and change often; they are not part of the dataset's verified core claim, and the file says so in `caveat`. The file depends only on the dataset, so it is byte-stable for a given dataset and pinned by the drift gate.

Its contract is **v1** and is described by a JSON Schema at a stable URL, [`/api/v1/models.schema.json`](https://freellmapihub.com/api/v1/models.schema.json) (the source is [`data/models.schema.json`](../data/models.schema.json)). The rules above apply: a field named below is never renamed, removed or retyped within v1, new fields may be added, so read only the fields you need and ignore the rest.

Top level, after the shared envelope:

| Field | Type | Meaning |
|---|---|---|
| `schema` | URL | the schema of this file |
| `page` | URL | the free model index |
| `caveat` | string | model lists are a sample and change often |
| `count` | integer | the number of models |
| `pairs` | integer | the number of (model, provider) rows |
| `models` | array | one record per model, sorted by `key` |

Each model has `key`, `name` (the most frequent bare ID), `page` (its model page), `indexable` (whether that page may be indexed: two or more verified providers list it), `provider_count` and `providers`, one row per provider in the order of the model page. Each row has:

| Field | Type | Meaning |
|---|---|---|
| `slug`, `name` | string | the provider |
| `model_id` | string | the exact ID the provider lists: the one to pass as `model` |
| `verified`, `last_verified` | boolean, date or null | whether the provider entry is verified, and the day it last was |
| `category`, `free_type`, `expires` | string or null | as in `providers.json` |
| `card_required`, `phone_required`, `commercial_ok`, `openai_compatible` | boolean or null | the provider's flags; `null` = not confirmed |
| `commercial_ok_condition` | string or null | the documented condition on commercial use |
| `openai_base_url` | URL or null | the OpenAI-compatible base URL |
| `data_policy` | object or null | `trains_on_prompts`, `retention`, `source`, `checked`; `null` when nothing is recorded |
| `limits_scope` | string | `model` (numbers the provider publishes for this exact ID, from `free_limits.per_model`), `provider` (the provider-wide numbers, not specific to this model), `none_published` (the provider publishes no numeric free limits) or `not_recorded` |
| `free_limits` | object or null | the numbers `limits_scope` names, with `scope`, `source` and `checked`; `null` for `none_published` and `not_recorded` |
| `provenance` | object | where the row can be checked: `source` (the provider's model catalogue, else its docs), `source_kind` (`models_url` or `docs_url`) and `checked` (the day the provider entry was last verified; `null` for an unverified entry) |

  "provider_count": 2,

    { "slug": "example", "name": "Example", "model_id": "openai/gpt-oss-120b", "verified": true, "last_verified": "2026-11-24",

### The change feed: `/api/v1/changes.json`

[`/api/v1/changes.json`](https://freellmapihub.com/api/v1/changes.json) is the field-level change feed as data: every change to a tracked provider field, with its value before and after, grouped by ISO week, newest week first. It covers the last 12 weeks that end at the week of the newest change (never anchored on the current date); weeks with no change are left out. It is mined from the git history of `data/providers.json` at build time, by the same code as the [What changed](https://freellmapihub.com/changes/) page and the RSS feed [`/changes.xml`](https://freellmapihub.com/changes.xml): each week of the JSON is the feed item with the same `guid`, and its `title` and `summary` are that item's title and description. One difference is deliberate: the JSON projects `commercial_ok` to `boolean | null` like every v1 file, so a change that only turns an unknown answer into a conditional one (`null` to `"conditional"`) is in the feed but not in the JSON, where both values are `null`; that week's counts then differ by those changes. Because it depends on the git history (a squash merge moves commit dates and hashes), the file is regenerated on every deploy and is not pinned by the drift gate.

Its contract is **v1** and is described by a JSON Schema at a stable URL, [`/api/v1/changes.schema.json`](https://freellmapihub.com/api/v1/changes.schema.json) (the source is [`data/changes.schema.json`](../data/changes.schema.json)). The fields `weeks` (`week`, `start`, `end`, `count`, `changes`) and, on each change, `date`, `slug`, `name`, `field`, `from` and `to` are the file's original shape and keep it. The fields marked 2.16.0 below were added in dataset 2.16.0 (unreleased).

| Field | Type | Meaning |
|---|---|---|
| `schema`, `page`, `feed` | URL | this file's schema, the What changed page, the RSS feed (2.16.0) |
| `fields` | array | the tracked fields in order, each `{ field, label }` (2.16.0): `free_tier`, `rate_limits`, `notes`, `free_type`, `commercial_ok`, `commercial_ok_condition`, `card_required`, `phone_required`, `openai_compatible` |
| `window_weeks` | integer | the window in weeks, 12 (2.16.0) |
| `count` | integer | the number of changes in the file (2.16.0) |
| `weeks` | array | one entry per week with a change, newest first |

Each week has `week` (ISO week, such as `2026-W48`), `start` (Monday), `end` (Sunday), `count`, `changes`, and since 2.16.0 `title`, `summary` and `guid` (the matching `changes.xml` item) and `providers` (the slugs with a change that week). Each change has:

| Field | Type | Meaning |
|---|---|---|
| `date` | date | the commit date of the change |
| `slug`, `name` | string | the provider; a provider that has left the dataset has its slug as `name` |
| `field` | string | one of the tracked fields of `fields` |
| `from`, `to` | string, boolean or null | the value before and after |
| `label` | string | the human label of `field` (2.16.0) |
| `commit` | string or null | the 40-character hash of the commit that made the change (2.16.0); a squash or rebase merge can give the same change a new hash, so it is a link, not an identifier |

Fields outside `fields` (limits, models, data policy) are not tracked yet: a change to them is not in this file.

### Generated client configs

`/api/v1/openai-clients.json` and `/api/v1/litellm.yaml` follow the same rules. Their *contents* follow the data: a provider enters or leaves them when it becomes, or stops being, verified and OpenAI-compatible with a known base URL and key variable. ## `version` in the data and the API path

Every API object carries `version` and `generated`, copied from `data/providers.json`:

- **`version`** is the dataset's [SemVer](https://semver.org/) release version, in lockstep with the `vX.Y.Z` Git tag (it is not a separate schema version). Minor and patch bumps are additive: a new field, a new file, a re-verification release. They stay on `/api/v1/`.
- **A new major `version`** is reserved for a breaking change to the shape, and is the release that introduces the next API path. The API path counts breaking changes to the API; it does not repeat the dataset's major number.
- **`generated`** is the date of the last dataset change (`YYYY-MM-DD`): the newest date recorded in the data (a provider's `last_verified`, `added`, `last_probed`, or the `checked` day of its data policy, free limits, no-expiry or anonymous-access statement), and never older than the dataset release. It is computed from the committed data, never from the clock. The canonical `data/providers.json` stores a different date in its own top-level `generated`: the day of the dataset release, which changes only with `version`; the build publishes the last-change date described here, so the meaning of the API field is unchanged. Provider-list payloads are byte-stable for fixed inputs. History and change feeds also depend on Git history; date-relative site outputs are described in [Architecture](architecture.md).

The provider-list payloads (`providers.json`, slices and modality lists) are described by [`/api/v1/schema.json`](https://freellmapihub.com/api/v1/schema.json). It is generated from [`data/schema.json`](../data/schema.json), but keeps the v1 representation: `commercial_ok` is `boolean | null`, while `commercial_ok_condition` may accompany `null`. The canonical schema remains wider and accepts `"conditional"`.

The published schema is also open where the canonical one is closed: every object that `data/schema.json` closes with `additionalProperties: false` (the envelope, each provider, and nested objects such as `field_checks`, `data_policy` or `free_limits`) is published with `additionalProperties: true`. A field the schema lists keeps its type, enum and `required` rule; only unknown keys are allowed, because v1 only ever adds fields. Copies of the schema fetched before dataset 2.15.0 are closed and reject fields added since; refresh them. The canonical `data/schema.json` stays closed on purpose: `scripts/validate.mjs` uses it to reject a misspelt or undeclared field in the dataset.

## Pinning a snapshot

The live API always serves the latest data. To pin one, use a Git tag: when `version` in `data/providers.json` advances on `main`, the `tag-release.yml` workflow creates the annotated tag `vX.Y.Z` for it. A tag pins the whole repository, data and generator included, so you can either read `data/providers.json` at that tag:

```bash
curl -s https://raw.githubusercontent.com/pacocartones/free-llm-api-hub/v2.9.1/data/providers.json
```

or check the tag out and run `npm ci --ignore-scripts && npm run build` to regenerate `/api/v1/` with that release's generator and inputs (history-derived endpoints also depend on the available Git history) under `site/api/v1/`.
